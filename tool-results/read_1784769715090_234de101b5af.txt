   233→  - Root cause: `fillSlot()` in meal-generator.ts used arbitrary gram caps (200g protein, 250g staple, 200g side) without respecting slot calorie target. Each item was sized independently of remaining slot calories, causing massive over-allocation (2249 kcal vs 1505 target = 49% over).
   234→  - Fix: Rewrote `fillSlot()` to be **calorie-aware**:
   235→    - Added `gramsForCal()` helper: calculates grams needed to hit a specific calorie target from a food, with reasonable min/max gram bounds
   236→    - Protein: targets 35% of *remaining* slot calories (was 35% of total slot), capped at 150g (was 200g)
   237→    - Staple/carb: targets 55% of *remaining* calories (was unlimited via remaining()), capped at 200g (was 250g)
   238→    - Side/veggie: targets 70% of *remaining* (was 100% of remaining), capped at 150g (was 200g)
   239→    - Snacks: calorie-capped to slot target (was capped at 150g regardless of calories)
   240→    - `remaining()` now returns `Math.max(0, ...)` to prevent negative overshoot
   241→  - Result: **Target 1667 kcal → Aktual 1676 kcal** (0.5% over, was 49% over). **Compliance: 90%** (was much lower). Per-slot actual % now matches target distribution (Sarapan 18% vs target 20%, Snack Pagi 10% vs 10%).

   270→- **Assessment → Calorie Engine Integration** (clinical accuracy improvement):
   271→  - Problem: `POST /api/meal-plan` and `POST /api/exercise` hardcoded `activity: "LIGHT"` and `stress: "NONE"` — ignoring the patient's actual clinical assessment (MUST/SGA/ECOG/Barthel/Frailty). This meant a bedridden patient (ECOG 4, Barthel 20) would get the same calorie target as an ambulatory one.
   272→  - Fix in `POST /api/meal-plan`:
   273→    - Added `assessments: { orderBy: { recordedAt: "desc" }, take: 1 }` to patient query include
   274→    - Fetch latest assessment and derive activity/stress:
   275→      - If `assessment.activity` is explicitly set → use it directly
   276→      - Else if `assessment.ecog` is set → derive: ECOG 0=MODERATE, 1=LIGHT, 2=VERY_LIGHT, ≥3=BED_REST
   277→      - Else if `assessment.barthel` is set → derive: <40=BED_REST, <60=VERY_LIGHT, else LIGHT
   278→      - If `assessment.stress` is set → use it (defaults to NONE if not assessed)
   279→    - Fallback: LIGHT/NONE if no assessment exists
